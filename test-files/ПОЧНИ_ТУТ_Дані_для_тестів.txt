15. НЕАКТУАЛЬНІ ДАНІ ТА ПРАВИЛА ДЛЯ НЕПОВНИХ ЗАПИСІВ
STALE: незавершений захід не оновлювався понад поріг (типово 30 днів).
У базовій демопрограмі є такі приклади. Шукайте сигнал «Дані потребують актуалізації».

запису цей сценарій одразу не відтворити, навіть якщо початок давній.

Звичайна форма не дозволяє погодити результат без опису/числа/фактичної дати.
Перевірте саме цю відмову. Окремі правила вже перевіряються командою npm test.
Рівень «Низький» присутній у фільтрах, але поточні правила його не генерують.

Адміністратор редагує наявного демонстраційного виконавця: змінює підрозділ, перевіряє призначення заходу та активність. Після перевірки відновлює початкові значення.

19. ПОШУК, ФІЛЬТРИ, СОРТУВАННЯ, ПАГІНАЦІЯ
Пошук «ТЕСТ-» → тестові заходи; пошук за кодом → конкретний запис.
Перевірте статус, виконавця, підрозділ, розділ, ризик і діапазон строків.
Сортування: строк / назва / оновлення, зростання й спадання.
Для пагінації відкрийте базову програму з 30 заходами: сторінки по 12 записів.
Перевірте порожній результат: введіть «НЕІСНУЮЧИЙ-ЗАХІД-999».
Скиньте текст і фільтри — записи повертаються.

20. АРХІВ, KPI ТА АУДИТ
Запишіть кількість активних заходів у тестовій програмі.
Створіть новий → загальна кількість +1.
Погодьте завершення → кількість виконаних +1.
Прогрес = виконані / активні * 100, округлення до цілого.
Архівуйте один тестовий захід із підтвердженням → активних -1.
Фільтр «Архівні» показує його, історія та файли зберігаються.
Відновіть → він повертається в активні.
Перевірте вкладку історії: автор, час, попередні й нові значення.
Під адміністратором перевірте загальний журнал і пошук за назвою дії.
Для рекомендацій: «Прийняти», «Відхилити», «Відкласти» змінюють стан
та створюють запис аудиту. Позначка сигналу «Взято до уваги» не прибирає причину.

21. АДАПТИВНІСТЬ І ЗБЕРЕЖЕННЯ
Звузьте вікно до планшета/телефона: меню відкривається кнопкою,
таблиці прокручуються, модальні форми доступні, календар зберігає 7 колонок.
Оновіть сторінку після збереження — значення не губляться.
Зупиніть і повторно запустіть сервер — записи мають залишитися в SQLite.

22. СКИДАННЯ — ЛИШЕ НАПРИКІНЦІ, ЯКЩО ГОТОВІ ВТРАТИТИ ВНЕСЕНІ ДАНІ
Адміністратор → Налаштування → Скинути демонстраційні дані.
Спочатку скасуйте дію: дані залишаються.
Підтвердьте словом СКИНУТИ лише якщо всі власні тестові дані вже не потрібні.
Очікування: початкові 30 заходів, 12 ризиків, 20 матеріалів; сесії завершені;
журнал аудиту збережено. Створені вами тестові програми/користувачі видаляються.
Безпечніша автоматична перевірка на окремій БД: npm run test:reset.

23. ГОТОВІ КОМАНДИ АВТОМАТИЧНОЇ ПЕРЕВІРКИ
Запустіть програму. У терміналі кореня проєкту:
  npm test
  npm run test:browser
  npm run test:reset
Якщо npm не знайдено, спочатку додайте локальний Node до PATH у цьому терміналі:
  $env:Path = "$PWD\.tools\node-v24.11.1-win-x64;$env:Path"
  npm.cmd test
API-тест створює і архівує тестовий захід; файли й аудит залишаються.
test:browser використовує Microsoft Edge. test:reset — окрему тестову БД.

24. ЩО ЦИМ НАБОРОМ НЕ ПЕРЕВІРЯЄТЬСЯ ЯК НАЯВНА ФУНКЦІЯ
Прямої інтеграції НАЗК/МОУ, імпорту таблиць у заходи, антивірусу, електронного
підпису та AI-читання змісту файлів немає. Не очікуйте цих дій після завантаження.
SHA-256 перевіряє байти, а не достовірність документа.
